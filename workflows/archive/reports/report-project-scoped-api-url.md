# Project-scoped API URL cleanup

## Request and root cause

The dashboard request included the project twice: `/forge/v1/projects/PROJECT-NODEFORGE/dashboard?project=PROJECT-NODEFORGE`.
The backend dashboard route already resolves project identity from the path. The duplicate query was generated by the UI client, not required by the backend.

## Implementation

- Dashboard requests now use `/forge/v1/projects/PROJECT-NODEFORGE/dashboard` without the redundant query.
- Extracted URL construction into `ui/nextjs/lib/node-client-url.js` to keep the client below the 250-line limit.
- The shared builder removes only a `project` query value identical to the project identity in `/projects/:id/...`.
- Other filters remain intact. Unscoped ticket/sprint endpoints still retain their required project query.
- A differing query identity is preserved rather than silently discarded; this change does not introduce a backend identity-conflict validator.
- Backend behavior is unchanged: legacy dashboard URLs containing the duplicate query remain accepted.
