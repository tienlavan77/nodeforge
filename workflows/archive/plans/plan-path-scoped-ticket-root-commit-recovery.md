# Plan — Path-scoped ticket root commit and audited recovery

**Status:** architecture/code plan; not implementation or acceptance evidence. Supersedes the root-commit portions of older worktree and shared-index plans for **new root-only executions**. Legacy worktree transactions require explicit migration/disposition; do not silently reinterpret their journals as root-only receipts.

## Decision and boundary

The project root is shared and may be dirty or staged for unrelated paths. Commit eligibility is determined by the Supervisor-owned ticket ledger, **not** `git status` of the whole root. A commit changes only ticket-owned manifest paths relative to a validated parent tree, using a private index, `commit-tree`, and branch `update-ref` compare-and-swap (CAS). Dirty/staged bytes outside the manifest are not candidate content, are not commit blockers, and are never cleaned. Do not reset, stash, `git add .`, or write `read-tree` into the shared index.

Path-scoped does **not** mean unconditional success: for every included path validate canonical identity, ownership/claim, policy, locked ledger revision and before/after checksums (including existence, deletion, mode and rename sides). An already-dirty path before the first ticket write is not silently adopted: isolate its ticket delta or require the existing explicit baseline authorization. The transaction is rejected on ticket-path drift or invalid provenance, not on unrelated dirt.

## Code changes in order

1. **Freeze the authority and scope** — `ticket-change-ledger.js`, `ticket-commit-file-service.js`, `ticket-file-lock.js`, `ticket-execution-context.js`, `ticket-root-commit-service.js`. Under the existing project commit lock plus ledger transaction lock, freeze `task_id`, `project_id`, branch, source revision, owner/claim IDs, operation IDs, sorted canonical changed paths, before/after existence and SHA, baseline authorization if any, and `manifest_sha`. `paths` supplied by an agent may only be validated against the ledger; they cannot silently narrow the commit. Reject path alias/symlink/rename escape and unjournaled metadata changes. Re-read only manifest paths immediately before staging and again before ref CAS; unknown after-SHA yields `TICKET_SOURCE_DRIFT`/`TICKET_PATH_CONFLICT`; conflicting claim yields `FILE_CLAIM_CONFLICT`. Preserve initial-before checks against the chosen parent or require explicit baseline reconciliation.
2. **Build a manifest-only candidate** — `ticket-root-git.js` and `ticket-root-commit-service.js`. Keep `GIT_INDEX_FILE` private for `read-tree <parent>`, literal path staging (or inject verified ledger blobs, including tombstones), `write-tree` and exact changed-path/blob/mode verification. Ensure all index-dependent Git calls use that private index. Do not read shared staged content into the candidate. Remove the shared-index staged-change veto, `index_sha` as a ticket gate, and `synchronize()`/shared-index `read-tree`. Preserve unrelated staged and unstaged *bytes*; note that advancing HEAD without updating the shared index can change how Git **displays** existing staged entries (even for ticket paths). Document this trade-off and explicitly test it; never claim the shared index remains semantically unchanged relative to the new HEAD.
3. **Commit and ref race** — Persist prepared journal with frozen identity, parent, branch and manifest checksums before creating objects; then record candidate tree and transaction-trailered commit SHA durably. Under the existing project commit lock, perform `update-ref <branch> <commit> <parent>` CAS. A moved branch is `TICKET_REF_CONFLICT`: do not force-advance, reset, or accept a candidate built on the stale parent. Recompute against the new parent under a **new** audited attempt only if each ticket before-state/baseline still matches; otherwise block for review. Once ref advances, a subsequent ticket may move HEAD: the first ticket's receipt/verification must reference its commit, tree, manifest and source revision rather than require `HEAD === commit`.
4. **Reconcile crash/stale journals, not source** — `ticket-root-commit-service.js`, `ticket-root-git.js`, and `ticket-resume.js`. Reconcile by `(project, task, ledger revision, transaction_id)` and journal phase. Validate parent/tree/commit trailer, committed paths/blob checksums, branch ancestry and ledger receipt; recover a proven ref-advanced commit idempotently even if later commits moved HEAD. A prepared journal lacking a provable commit is **not** proof the ticket completed: append an audited `quarantined`/`needs_human_review` disposition or an explicitly safe `reconciled_no_ref_move` disposition; preserve original record and never erase, overwrite, or auto-adopt its source. A proven orphaned commit whose CAS never succeeded remains nonterminal until an authorized, revalidated new attempt. Avoid unbounded `fsck` as the only recovery mechanism; record commit-object identity before CAS and bound legacy discovery. Audit phase changes, reason, identities and actor without source/secrets. `TICKET_COMMIT_RECOVERY_CONFLICT` is reserved for ambiguous/contradictory transaction identity, never for unrelated dirty paths.
5. **Legacy worktree route** — `ticket-commit-service.js` currently tests `changed.some(path => !expected.includes(path))` on recovery. Replace this with proof of the prepared transaction's exact commit/paths/parent and ledger revision; do not blindly remove the check and accept an unrelated HEAD. If old `pending_commit` lacks transaction proof, quarantine/escalate rather than infer success from status. Do not mix worktree receipts with root-only journals.
6. **Downstream gates** — `ticket-verification-service.js`, `ticket-review-evidence.js`, `ticket-approved-integration.js`, `terminal-receipt-writer.js`. Verify the exact committed tree and passed artifact bound to `commit_sha`, `tree_sha`, `manifest_sha`, source revision and baseline. Review required findings on newer revisions with evidence; no retry-as-pass on a failed same revision. Integration happens only after approval, rechecks artifact/commit identity, and writes terminal receipt before claim release. An integration failure moves to `needs_human_review`, not a fake terminal success. Root-only integration may be verify-only for a commit already on branch; later HEAD advancement is allowed when ancestry and exact commit evidence hold.

## Failure mapping

| Condition | Action |
| --- | --- |
| Dirty/staged path outside ticket manifest | Ignore for commit eligibility; do not modify it. |
| Manifest path changed since last Forge write, or candidate blob/mode differs | Block `TICKET_SOURCE_DRIFT` / `TICKET_PATH_CONFLICT`, retain claims and evidence. |
| Owner/claim or before-baseline identity differs | `FILE_CLAIM_CONFLICT` / `TICKET_BASELINE_CONFLICT`; require resolution. |
| Parent branch ref changes before CAS | `TICKET_REF_CONFLICT`; no forced commit or silent retry. |
| Journal identity ambiguous, missing transaction evidence, or contradictory receipt | Quarantine/audit; `needs_human_review` as appropriate. |
| Verification/review/integration identity mismatch | Fail closed; do not approve, terminalize or release claims. |

## Tests and rollout gates

- Extend `backend/tests/integration/ticket-root-commit.test.js` and `ticket-root-concurrency.test.js`: dirty and staged unrelated files survive without blocking; committed diff contains *only* ticket paths; shared index bytes are not written by the commit service; deleted/new/rename paths and file modes obey ledger; dirty pre-claim ticket baseline is not adopted; same-path race/drift blocks; branch CAS race never force-moves ref.
- Crash-inject after journal prepared, candidate tree, commit object, CAS and receipt persistence. Assert proven transactions recover once, stale/ambiguous journals are durably audited and quarantined, and outside-manifest dirt cannot produce `TICKET_COMMIT_RECOVERY_CONFLICT`. Keep unrelated staged content and source intact.
- Extend `backend/tests/integration/ticket-workspace-service.test.js` / `immutable-ticket-pipeline.test.js`: ticket A verifies/reviews its exact commit after disjoint ticket B moves HEAD; failed same-revision verification stays blocked; approval-only integration and terminal receipt/claim release are enforced; integration failure goes to human review.
- Migrate behind a project-scoped shadow gate: inventory in-flight prepared journals and old index-sync receipts, classify by verifiable identity; do not auto-upgrade unprovable historical transactions. Run targeted tests and real restart/concurrency witness; record commands, results and redacted receipts before enabling enforcement.
- **A5 remains separate:** technical pipeline success alone does not close the A5 ticket. Require actual HTTP, SSE, Node client and UI error-consumer audit plus the historical 18 JSONL / 2,305-message corpus (including 50 legacy-field messages), and documented adapter removal or explicit human extension. Until A4/A5 release gates and human decision pass, keep `shadow`; do not open A6.

**Exit criterion:** two disjoint concurrent tickets commit independently while unrelated root/index changes survive; any manifest-path or transaction conflict fails closed; journal reconciliation leaves a durable audit; verification → review → approved integration uses identical immutable evidence. No code has been changed by this plan.
