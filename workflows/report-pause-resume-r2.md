## Cách thực hiện và tiêu chí chốt

1. **Môi trường:** project fixture tạm, fake SDK có call counters + abort/session hooks, File Service bền vững, hai instance Control API khi test lease; remote chỉ là local bare repo tạm. Không dùng project hoặc remote sản xuất để inject crash/push.
2. **Chạy từ hẹp đến rộng:** trước tiên `node --test backend/tests/unit/owner-execution-checkpoint.test.js`; sau khi có tests bổ sung thì chạy từng file unit/integration của execution, sau đó UI e2e và build UI. Lưu run ID, exit code, số case pass/fail và checkpoint/remote SHA trước/sau cho từng outcome. Build timeout phải chạy lại hoặc ghi **chưa kiểm chứng**, không coi là pass.
3. **Negative tests:** với mọi boundary có thể lặp side effect, inject lỗi ở trước call, sau side effect/trước receipt, sau receipt, khi process cũ còn sống; đối chiếu số lần tool/commit/push thực sự chạy. Nếu thiếu receipt hoặc không đọc được remote thì hệ thống **phải chặn**, không tự tiếp tục.
4. **Gate production:** chỉ khi O1–O6 có đủ bằng chứng pass (bao gồm manual recovery thành công, lỗi bị chặn đúng, e2e UI), authorization đúng và reviewer đối chiếu từng acceptance criterion tại `workflows/plan-pause-resume-r2.md:97` mới đề xuất nghiệm thu. Hiện tại **NO-GO**.
