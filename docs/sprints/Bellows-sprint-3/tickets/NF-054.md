# NF-054 — Integration Test End-to-End (2 Luồng)

**Sprint:** 3 (Bridge)  
**Type:** Integration Test  
**Estimate:** M (Medium)  
**Dependencies:** NF-049, NF-050, NF-051, NF-052, NF-053  
**Phụ thuộc:** Tất cả ticket Sprint 3 đã done phải xong trước (48–53)

---

## Mục Tiêu

Build end-to-end integration test xác nhận **toàn bộ chuỗi Agent Protocol** hoạt động đúng từ đầu đến cuối:
- **Luồng (a) — Builder:** Agent spawn → `sessions.start` → ghi file → Node watcher detect → Code Index cập nhật → `sessions.finish`
- **Luồng (b) — Reviewer:** Agent khác spawn → đọc file via Code Index (không viết file trung gian) → verdict về Node qua Event có cấu trúc

**Quan trọng:** Xác nhận **không có file "handoff" trung gian nào** (`review.md`, `builder-report.md`, vv) được tạo ra — Agent giao tiếp qua Node, không file.

## Acceptance Criteria

### Luồng (a) — Builder Flow

- [ ] Agent fixture A spawn đúng (process độc lập, NDJSON wire format)
- [ ] Agent A gửi `sessions.start` command → Node tạo session record
  - [ ] Session có `session_id`, `agents: [agent_a_id]`
  - [ ] `capability_scopes` được validate + lưu (NF-053)
- [ ] Agent A ghi file thật vào project fixture: `src/auth.js` (mock code)
  - [ ] File được lưu thực tế trên filesystem
  - [ ] stdout/stderr capture được qua `internalBus` (NF-051)
- [ ] Node watcher detect file change (tái dùng Sprint 1 pipeline NF-023 nguyên vẹn)
  - [ ] File event phát lên `internalBus` (xác nhận không bị dính với agent stream)
  - [ ] Code Index update (NF-017–022 đã có, chỉ xác nhận index.db có entry `src/auth.js`)
- [ ] Agent A gửi `sessions.finish` command → Node đóng session
  - [ ] Session record vẫn tồn tại (readable, không delete — đúng NF-044)
  - [ ] Process A không còn zombie (PID check lúc finish)
  - [ ] Không leak handle/file descriptor

### Luồng (b) — Reviewer Flow (Mới, không có trong Sprint 3 trước)

**Context:** Sau luồng (a) xong, file `src/auth.js` đã có trong project fixture + index.

- [ ] Agent fixture B spawn độc lập (khác session_id với A)
- [ ] Agent B gửi `sessions.start` command → Node tạo session record riêng
  - [ ] Session B có `session_id` khác A, `agents: [agent_b_id]`
- [ ] Agent B **đọc** file `src/auth.js` (qua Code Index, không file trung gian)
  - [ ] Xác nhận: Agent B dùng API/interface Node cung cấp để query symbol/file content
  - [ ] **Không** tạo file `review.md` hoặc bất kỳ file trung gian nào
- [ ] Agent B phát hiện lỗi mock (script fixture chỉ định sẵn 1–2 issue nhỏ trong file)
- [ ] Agent B gửi `review.requested` event (hoặc tương đương review verdict command)
  - [ ] Payload có cấu trúc: `{ result: "changes_required", findings: [...], ...}` khớp schema
  - [ ] Event validate qua Ajv với `core/event.schema.json` (hoặc `node-event.schema.json` nếu Node phát)
- [ ] Node nhận event → lưu (nơi nào: Event Store hay tạm thời?)
- [ ] Agent B gửi `sessions.finish` → Node đóng session B
- [ ] **Filesystem check:** `git status` xác nhận **không có file mới** được tạo
  - [ ] Chạy `git status` sau cả 2 luồng → chỉ `src/auth.js` modified (từ A), không có `review.md` / `*.md` / bất kỳ artifact nào khác

### Toàn Chuỗi (Cross-Luồng)

- [ ] 2 session hoạt động **độc lập** (không can thiệp lẫn nhau)
  - [ ] Session A stream **không bị trộn** vào Session B stream
  - [ ] Request ID / session ID routing đúng (NF-050 idempotency)
- [ ] Timeout/kill (NF-052) — không xảy ra (fixture tính toán thời gian)
- [ ] Concurrent modification (NF-055) — **nếu 2 agent cùng lúc sửa 1 file:**
  - [ ] Node phát warning event (NF-055 milestone, nhưng xác nhận không gây crash ở NF-054)
  - [ ] Cả 2 lần ghi vẫn thành công
  - [ ] Cả 2 session vẫn close sạch

### Test Runner Pseudocode

```javascript
describe('Agent Protocol E2E', () => {
  let project, node, builderProcess, reviewerProcess;
  
  before(async () => {
    // Setup: create project fixture, start Node server
    project = createProjectFixture();
    node = startNodeServer(project.path);
  });
  
  describe('Luồng (a) — Builder', () => {
    it('should spawn Agent A, start session, write file, finish', async () => {
      builderProcess = spawnAgent('agent-builder.js');
      
      // Wait for sessions.start event from Node
      const sessionStart = await node.waitForEvent('sessions.start');
      assert(sessionStart.session_id);
      
      // Wait for file to appear
      await waitFor(() => fs.existsSync('src/auth.js'), 5000);
      
      // Watcher detects file
      const fileEvent = await node.waitForEvent('file.modified');
      assert.include(fileEvent.path, 'src/auth.js');
      
      // Index updates
      await waitFor(() => {
        const indexed = node.codeIndex.getFile('src/auth.js');
        return indexed !== null;
      }, 5000);
      
      // Wait for sessions.finish
      const sessionFinish = await node.waitForEvent('sessions.finish');
      assert(sessionFinish.session_id === sessionStart.session_id);
      
      // Verify no zombie process
      assert(!isProcessAlive(builderProcess.pid));
    });
  });
  
  describe('Luồng (b) — Reviewer', () => {
    it('should spawn Agent B, read file, send verdict, no handoff file created', async () => {
      // Verify builder file exists from luồng (a)
      assert(fs.existsSync('src/auth.js'));
      
      reviewerProcess = spawnAgent('agent-reviewer.js');
      
      // Wait for sessions.start
      const sessionStart = await node.waitForEvent('sessions.start');
      assert(sessionStart.session_id);
      assert.notEqual(sessionStart.session_id, builderSession.session_id);
      
      // Agent requests file via Code Index (not direct read)
      // → Simulated: Node sends context.ready with file content
      const contextReady = await node.waitForEvent('context.ready');
      assert(contextReady.file_content);
      
      // Wait for verdict event
      const verdict = await node.waitForEvent('review.requested');
      assert.deepInclude(verdict, {
        result: 'changes_required'
      });
      assert(Array.isArray(verdict.findings));
      
      // Session finish
      const sessionFinish = await node.waitForEvent('sessions.finish');
      
      // **CRITICAL:** Verify NO handoff file exists
      const gitStatus = execSync('git status --porcelain').toString();
      assert(!gitStatus.includes('review.md'));
      assert(!gitStatus.includes('builder-report'));
      assert(!gitStatus.match(/^\?\?.*\.(md|txt|json)$/m)); // no new artifact files
      
      // Only src/auth.js should be modified
      assert(gitStatus.includes('src/auth.js'));
    });
  });
  
  after(async () => {
    // Cleanup
    if (builderProcess) builderProcess.kill();
    if (reviewerProcess) reviewerProcess.kill();
    await node.close();
    await project.cleanup();
  });
});
```

## Rủi ro & Hướng Xử Lý

| Rủi ro | Hệ quả | Xử Lý |
|--------|--------|-------|
| Agent fixture không exit dứt khoát (hang process) | Test timeout, CI blocked | Set `timeout: 30000ms` trên test + watchdog kill |
| Reviewer agent tạo file `review.md` "thêm info" | Xung đột nguyên tắc "no handoff file" | Xác nhận fixture reviewer không tạo file — nếu cần, chỉ phát event |
| Concurrent modification không được test ở NF-054 | NF-055 không có coverage | Thêm 1 scenario nhỏ: 2 agent ghi cùng file trong 100ms → verify warning event, không crash |
| Code Index query API chưa implement (NF-017–022 không hoàn) | Reviewer luồng bị block | Fallback: query trực tiếp `index.db` qua SQLite nếu API chưa có; document "đợi NF-XXX implement API" |
| Stream capture bị interleave (Agent A stream trộn Agent B stream) | Bug ẩn trong channel separation | Verify `internalBus` channel riêng (`agent.stdout:sessionA` vs `agent.stdout:sessionB`) — xem NF-051 |

## Ghi Chú Cho Builder

### Tại Sao Luồng (b) Quan Trọng?

Lý do chính từ `ARCHITECTURE.md` mục 66.8 + phiên trao đổi mới:

> **"Agent không giao tiếp trực tiếp với nhau qua file trung gian. Builder ghi code trực tiếp. Reviewer đọc code qua Node (Code Index), gửi verdict về Node dưới dạng Event có cấu trúc — không có file handoff."**

Sprint 3 chỉ test luồng Builder → file. NF-054 bổ sung luồng Reviewer để xác nhận:
- ✅ Reviewer có thể đọc file (query Code Index)
- ✅ Reviewer phát verdict qua Event (không file)
- ✅ Workflow hoàn chỉnh: Builder file → Node detects → Code Index → Reviewer reads → verdict Event

Nếu bỏ luồng (b), không xác nhận nguyên tắc "no Agent-to-Agent file handoff" — nguy hiểm lúc lên Sprint 6 (Workflow Engine) sẽ tưởng nhầm file trung gian vẫn được dùng.

### API Cho Reviewer Để Query Code Index

Builder cần xác nhận **API nào** Reviewer dùng để đọc file:

```javascript
// Option 1: Node phát context.ready event kèm file content
// → Reviewer nhận qua stdout, parse Event

// Option 2: Reviewer call Node API qua HTTP/gRPC query
// → Cần "đợi Sprint 8 Transport implement"

// Option 3: Query index.db trực tiếp (SQLite, tạm thời)
// → Valid nếu API chưa có, nhưng comment "temporary, API TBD"
```

**Ghi rõ trong test:** Builder chọn option nào + lý do.
