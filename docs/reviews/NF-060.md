## Findings

- `test-result` supports Node-owned test execution evidence: status, exit code, timing,
  optional test counts, per-test failures, and output.
- `check-result` supports the combined build/lint/typecheck runner through its required
  `kind` enum and optional diagnostics with file, line, column, and rule ID.
- `verification-plan` owns the reusable verification-level and check-type enums.
  `verification-run` and `roadmap/commit` reference those definitions instead of copying them.
- `verification-run` keeps individual result records by `result_ref`, while
  `verification-result` is the workflow-facing gate and `verification-policy` owns retry and
  stop-on-failure configuration.
- `test-failure` is a bounded normalized failure-evidence contract; it intentionally remains
  separate from the stored test-result record.
